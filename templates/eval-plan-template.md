# 평가 작업판 (eval-plan) — 템플릿

> 평가총괄이 **평가마다**(사업이 하나여도) 이 템플릿을 Read로 읽어 사용자 작업 폴더의 `.omo/eval-plan.md`에 Write로 쓴다. 작업판이 없으면 완료 엔진이 꺼진다.
> **완료 엔진(Stop hook)**이 이 파일의 `- [ ]`(미완료)를 감지해, 하나라도 남아 있으면 평가를 멈추지 못하게 한다.
>
> - `[x]` = 완료
> - `[ ]` = 미완료 (남아 있으면 완료 엔진이 계속 일하게 만듦)
> - `[~]` = 외부 자료 대기 등으로 막힘 (사유 명기 / 미완료에서 제외됨)
>
> 여러 사업(합본 포함)을 평가하면 사업별로 블록을 복제하고, 블록 제목에 사업 폴더 `.omo/<사업 약칭>/`를 적는다.

## 공통

- [ ] 원문 텍스트화 (`deveval-extract` → `.omo/sources/`, 변환 경고 확인)
- [ ] 사업 경계 판별 (합본이면 사업별 블록·폴더로 분리)

## 사업: <사업명> · 폴더 `.omo/<사업 약칭>/` (사업유형: <유형>)

- [ ] 자료 확인 및 사업유형 판별
- [ ] 원문 사실대장 작성 (한 표기당 한 행 / 같은 사실 F-ID 재사용 / 값·단위·분모·기간·집계규칙·기준일·위치)
- [ ] 사실대장 비교축 차이 설명 또는 상충 후보 등록 및 `auditable_output_check.py --ledger-only` 통과
- [ ] 적절성(Relevance) 평가
- [ ] 일관성(Coherence) 평가
- [ ] 효과성(Effectiveness) 평가
- [ ] 효율성(Efficiency) 평가
- [ ] 지속가능성(Sustainability) 평가
- [ ] 근거·점수·원문 사실대장 검증 (quality-verifier)
- [ ] 전역 상충·불일치 등록부 확정 (F-ID / X1… / 해결 상태 / 점수·결론 영향)
- [ ] 검증 정정 적용 및 **검증 후 점수** 재산정 (5기준 20점 → A~F)
- [ ] 감사 가능한 브리프 작성 (원문 사실대장·[사실: Fn] 상세근거·반대근거·상충·평가불가·정정·한계)
- [ ] 산출물 계약·수치 일관성 검사 후 사람 인계
