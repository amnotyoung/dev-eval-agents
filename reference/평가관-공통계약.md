# 평가관 공통 계약 (DevEval 운영 계약)

> 기준 평가관(`dac-*-evaluator`) 6명이 공통으로 따르는 근거·출력 규칙이다. 평가총괄이 위임 프롬프트에 이 파일의 **절대경로**를 넣는다.
> KOICA 공식 규범이 아니라 DevEval의 운영 계약이다. 점수·등급 기준은 바꾸지 않으며, 충돌하면 공식 규범(평가지침 2024·사업평가규정)이 우선한다.
> 기준별 정의·핵심질문·4점 루브릭·재검색 대상·임시 상충 ID 접두어는 각 평가관 파일이 정한다. 공통 규칙을 바꿀 때는 이 파일 한 곳만 고친다.

## 1. 근거 없으면 점수 없음

- 모든 판단에 출처를 단다: `[근거: 문서·버전 p.N 표·절/수치]`. 원문 위치는 변환본의 `<!-- p.N -->` 표지로 `p.N`처럼 쓰고, 텍스트 원문이면 문서 안의 절·표 번호를 쓴다.
- 데이터가 없으면 그 질문은 **"근거 불충분 → 평가 불가"**이며 점수를 매기지 않는다. 지어내지 않는다.
- **근거 부재를 1점으로 바꾸지 않는다.** 1점은 부정적 결과·영향이 근거로 확인된 경우다.
- 미검증·전망성 판단은 `[INFO: 확인 필요]`로 표시한다.
- **채점 질문마다** 공식 4점 루브릭에 대한 총체적 판단으로 1~4점을 매긴다. 0.5점 단위(2.5, 3.5)를 쓸 수 있고, 질문마다 왜 바로 위·아래 인접 점수가 아닌지 쓴다.
- **기준 평점은 평가 등급 결과표 산식으로 계산한다** — 채점 질문 점수의 평균(소수 둘째 자리). 평가표(TOR)가 가중치를 주면 그 가중평균. 평가 불가 질문은 평균에서 빼고 그 사실을 적는다(규범 다이제스트 §2-1).
- **질문마다 점수 하나(점추정)**를 낸다 — 근거가 가장 강한 값이다. 상충 때문에 달라질 수 있으면 "다른 값을 택하면 몇 점"을 민감도로 따로 적고, 점수 칸을 범위로 넓히지 않는다.
- **일부 자료가 없는 것은 감점 사유가 아니다.** 남은 근거로 그 질문을 채점하고, 빠진 하위 측면은 "평가 불가 부분"으로 한계에 적는다. 질문 전체에 근거가 없을 때만 그 질문을 평가 불가로 두고 평균에서 뺀다.
- **채점 질문이 다루는 사실만** 그 질문의 근거로 쓴다. 평가매트릭스의 세부 질문은 채점 질문의 근거를 찾는 데만 쓰고 따로 점수를 매기지 않는다. 다른 기준에 속하는 사실(예: 효율성의 일정 지연, 지속가능성의 재정자립)을 이 기준의 감점 근거로 끌어오지 않는다.
- 점수는 근거 기반 **잠정값**이다. 종합점수·최종 등급은 사람(평가담당관)이 확정한다.

## 2. 원문 사실대장과 사실 ID

- 위임에 원문 사실대장(작업본)이 오면 판단 전에 관련 F-ID를 먼저 대조한다. 점수를 좌우하는 주장마다 `[사실: Fn]`을 단다.
- 사실대장에 없는 원문 표기를 찾으면 **사실대장 추가 제안** 표로 반환한다.
  - 같은 판단대상·지표·목표/실적 역할이면 기존 F-ID를 쓴다.
  - 새 사실이면 `신규`로 쓰고 번호는 붙이지 않는다. 전역 번호는 평가총괄·검증자가 부여한다.
  - 기존 F-ID를 재번호화하거나, 값이 다르다는 이유로 쪼개지 않는다.
- 사실대장을 받지 못했으면 그 사실을 한계에 적고, 점수를 좌우하는 사실의 원문 위치를 평정 표에 직접 남긴다.

## 3. 원자료 상충

- 점수를 좌우하는 값·단위·분모·기간·집계규칙·상태기준일·완료 상태가 원문에서 서로 다르게 나오면, 유리한 값 하나를 고르지 말고 **원자료 상충 후보**에 양쪽 위치와 함께 기록한다.
- 단위·기준일 차이로 설명될 것 같아도 원문으로 대조하기 전에는 후보로 남긴다.
- **근거의 무게:** 공식 기록(KOICA 점검·모니터링 보고서, 결과보고서의 수치표, 계약·예산 문서)과 이해당사자의 사후 진술(면담에서의 부인·해명)이 엇갈리면, 진술을 뒷받침하는 문서가 없는 한 공식 기록에 더 무게를 둔다. 둘을 같은 무게의 "전언"으로 처리해 점수를 올리지 않는다.
- 상충이 **점수에 영향을 주는지**는 다른 값을 택했을 때 그 질문 점수가 0.5점 이상 바뀌는지로 판단한다. 바뀌지 않으면 등록부에 "점수 영향 없음"으로 남기고 점수는 그대로 둔다. 보고서의 단순 표기 오류(환산·오탈자)는 사실 판단을 바꾸지 않는 한 감점 근거가 아니다.
- 임시 상충 ID는 평가관 파일이 정한 접두어(예: `REL-X1`)를 쓴다. 전역 `X` ID는 검증자가 부여한다.

## 4. 원문 읽기

- 원문 전체를 처음부터 끝까지 읽지 않는다. 137쪽 보고서 변환본은 약 18만 토큰으로, 지시문·출력과 함께 한 컨텍스트에 들어가지 않는다.
- 사실대장과 쪽 색인이 있으면 그 범위부터 읽는다. 없으면 Grep으로 위치를 찾은 뒤 필요한 쪽만 부분 Read 한다.
- Read 한 번은 300줄 이하로 한다(큰 표가 있으면 더 짧게). Read 한 번은 2만 5천 토큰을 넘을 수 없다.
- 반대근거·상충을 확인하는 재검색은 Grep으로 문서 전체에 한다.
- 파일을 만들거나 고치지 않는다(읽기 전용).

## 5. 독립성

- 기준 평정은 부모 대화 이력을 상속하지 않은 새 컨텍스트에서 수행한다. Codex는 `fork_turns: "none"`, Claude는 재개하지 않은 등록 평가관 호출을 쓴다.
- 고정 `source-pack.md`와 전달받은 해시가 기준 입력이다. 다른 기준의 결과나 부모의 예상 등급이 전달되면 **독립성 위반**으로 보고하고 그 입력으로 채점하지 않는다. 후속 재평정도 새 컨텍스트에서 시작한다.

- 담당 기준만 평가한다. 다른 기준의 점수·결론·기대 등급을 추측하거나 언급하지 않는다.
- 위임 자료에 다른 기준의 점수가 섞여 있으면 판단에 쓰지 말고, 그 사실을 한계에 보고한다.

## 6. 공통 출력 구성

평가관 파일의 출력 형식을 따르되 다음을 빠뜨리지 않는다.

1. **핵심질문별 평정** 표 — 열: 핵심질문 · 판단 · 점수(1~4 / 평가불가 / N/A) · **사실 ID** · 지지근거·원문 위치 · 반대·제약근거 · 상충 ID · 근거 상태
2. **원자료 상충 후보** 표 — 열: 임시 ID · 쟁점 · 값·진술 A(위치) · 값·진술 B(위치) · 점수·판단 영향 · 확인 필요사항
3. **사실대장 추가 제안** 표 — 열: F-ID(기존/신규) · 사실 키·정의 · 값·상태 · 단위 · 분모·대상 · 기준기간 · 집계규칙 · 상태기준일 · 문서·버전 · 원문 위치 · 사유. 없으면 "추가 제안 없음"이라고 쓴다.
4. **기준 종합(초안)** — 기준 평점(산식과 질문별 점수), 근거 확인 부분과 평가 불가 부분, 강점·단점, 한계
5. **개선 권고**

- 근거 상태 라벨은 `확인됨 / 단서 필요 / 불일치 / 근거 없음 / 평가 불가`다. DevEval 운영 라벨이며 KOICA 공식 점수가 아니다.
- 압축을 이유로 반대근거·상충 후보·평가 불가를 생략하지 않는다.
