# Common Evaluator Contract (DevEval operating contract)

> Evidence and output rules shared by the six criterion evaluators (`dac-*-evaluator`). The lead evaluator puts the **absolute path** of this file into every delegation prompt.
> This is DevEval's operating contract, not an official KOICA norm. It does not change scoring or grading rules; on any conflict the official norms (Evaluation Guidelines 2024 and the Project Evaluation Regulation) prevail.
> Each evaluator file defines its own criterion, key questions, 4-point rubric, re-search targets, and local conflict-ID prefix. To change a shared rule, edit this one file only.

## 1. No evidence, no score

- Cite a source for every finding: `[Evidence: document·version p.N table·section/figure]`. Give source locations with the converted copy's `<!-- p.N -->` markers as `p.N`; for a plain-text source, use the document's own section or table numbers.
- If there is no data, the question is **"insufficient evidence → cannot evaluate"** and gets no score. Do not fabricate.
- **Never turn missing evidence into a score of 1.** A 1 means a negative result or effect is confirmed by evidence.
- Mark unverified or forward-looking judgments as `[INFO: needs confirmation]`.
- The provisional criterion score is a holistic judgment against the official rubric, not a mechanical average of question scores. State why it is not the adjacent higher or lower score.
- Scores are evidence-based **provisional values**. The composite score and final grade are confirmed by a human (the evaluation officer).

## 2. Source-fact ledger and fact IDs

- If the delegation includes a source-fact ledger (working copy), check the relevant F-IDs before judging. Attach `[Fact: Fn]` to every score-critical claim.
- When you find a source occurrence missing from the ledger, return it in the **Fact-ledger additions** table.
  - Use the existing F-ID for the same decision object, indicator, and target/actual role.
  - Write `new` for a new fact and leave it unnumbered. The lead evaluator and verifier assign global numbers.
  - Never renumber an existing F-ID or split one because the values differ.
- If no ledger was provided, say so in the limitations and record the source location of every score-critical fact directly in the rating table.

## 3. Source conflicts

- When score-critical values, units, denominators, periods, aggregation rules, as-of dates, or completion status differ across the source, do not pick the favorable value. Record both locations under **Source-conflict candidates**.
- Keep a difference as a candidate until it is reconciled against the source, even if units or as-of dates seem to explain it.
- Use the local conflict-ID prefix defined in your evaluator file (for example `REL-X1`). The verifier assigns global `X` IDs.

## 4. Reading the source

- Do not read the whole source from start to finish. The converted copy of a 137-page report is about 180,000 tokens and does not fit in one context together with instructions and output.
- Start from the ledger and page index when provided. Otherwise locate passages with Grep and Read only the pages you need.
- Keep each Read to 300 lines or fewer (fewer when large tables are present). A single Read cannot exceed 25,000 tokens.
- Re-search for counterevidence and conflicts across the whole document with Grep.
- Do not create or modify files (read-only).

## 5. Independence

- Evaluate only your assigned criterion. Do not guess or mention other criteria's scores, conclusions, or expected grades.
- If the delegated material contains other criteria's scores, do not use them, and report that in the limitations.

## 6. Shared output structure

Follow your evaluator file's output format and always include:

1. **Rating by key question** table — columns: Key question · Finding · Score (1–4 / cannot evaluate / N/A) · **Fact ID** · Supporting evidence and source location · Counter/constraint evidence · Conflict ID · Evidence status
2. **Source-conflict candidates** table — columns: Local ID · Issue · Value/statement A (location) · Value/statement B (location) · Effect on score/finding · Follow-up needed
3. **Fact-ledger additions** table — columns: F-ID (existing/new) · Fact key and definition · Value/status · Unit · Denominator/population · Reference period · Aggregation rule · As-of date · Document·version · Source location · Reason. If there are none, write "No additions".
4. **Criterion summary (draft)** — provisional score, why not the adjacent scores, evidence-confirmed and cannot-evaluate parts, strengths and weaknesses, limitations
5. **Improvement recommendations**

- Evidence-status labels are `confirmed / needs qualification / inconsistent / no evidence / cannot evaluate`. They are DevEval operating labels, not official KOICA scores.
- Never omit counterevidence, conflict candidates, or unevaluable items for concision.
