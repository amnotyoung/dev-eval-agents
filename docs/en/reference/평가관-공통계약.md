# Common Evaluator Contract (DevEval operating contract)

> Evidence and output rules shared by the six criterion evaluators (`dac-*-evaluator`). The lead evaluator puts the **absolute path** of this file into every delegation prompt.
> This is DevEval's operating contract, not an official KOICA norm. It does not change scoring or grading rules; on any conflict the official norms (Evaluation Guidelines 2024 and the Project Evaluation Regulation) prevail.
> Each evaluator file defines its own criterion, key questions, 4-point rubric, re-search targets, and local conflict-ID prefix. To change a shared rule, edit this one file only.

## 1. No evidence, no score

- Cite a source for every finding: `[Evidence: document·version p.N table·section/figure]`. Give source locations with the converted copy's `<!-- p.N -->` markers as `p.N`; for a plain-text source, use the document's own section or table numbers.
- If there is no data, the question is **"insufficient evidence → cannot evaluate"** and gets no score. Do not fabricate.
- **Never turn missing evidence into a score of 1.** A 1 means a negative result or effect is confirmed by evidence.
- Mark unverified or forward-looking judgments as `[INFO: needs confirmation]`.
- **Score each scored question** 1–4 as a holistic judgment against the official 4-point rubric. Half points (2.5, 3.5) are allowed; for each question, state why it is not the adjacent higher or lower score.
- **The criterion formula is the mean of the scored questions** (two decimals), or the weighted mean supplied by the evaluation table (TOR). `score_calculate.py` performs the actual means, rounding, totals and grade mapping. Evaluators supply only question judgments and scores, not hand-calculated criterion ratings. Unscored questions are excluded and disclosed in the generated table (normative digest §2-1).
- Give **one score per question (a point estimate)** — the best-supported value. If a conflict could change it, record "choosing the other value gives N" as sensitivity; do not widen the score cell into a range.
- **Partly missing data is not a reason to lower a score.** Score the question on the remaining evidence and record the missing sub-aspect as a "cannot-evaluate part" in the limitations. Only when a whole question lacks evidence is it cannot-evaluate and left out of the mean.
- Use **only facts the scored question covers** as its evidence. Use the evaluation matrix's sub-questions only to find evidence for the scored questions, never as separately scored items. Do not import facts that belong to another criterion (e.g. Efficiency's schedule delay, Sustainability's financial self-reliance) as penalties here.
- Scores are evidence-based **provisional values**. The composite score and final grade are confirmed by a human (the evaluation officer).

## 2. Source-fact ledger and fact IDs

- If the delegation includes a source-fact ledger (working copy), check the relevant F-IDs before judging. Attach `[Fact: Fn]` to every score-critical claim.
- When you find a source occurrence missing from the ledger, return it in the **Fact-ledger additions** table.
  - Use the existing F-ID for the same decision object, indicator, and target/actual role.
  - Write `new` for a new fact and leave it unnumbered. The lead evaluator and verifier assign global numbers.
  - Never renumber an existing F-ID or split one because the values differ.
- If no ledger was provided, say so in the limitations and record the source location of every score-critical fact directly in the rating table.

## 3. Source conflicts

- When score-critical values, units, denominators, periods, aggregation rules, as-of dates, or completion status differ across the source, do not pick the favorable value. Record both locations under **Source-conflict candidates**.
- Keep a difference as a candidate until it is reconciled against the source, even if units or as-of dates seem to explain it.
- **Weight of evidence:** when official records (KOICA inspection and monitoring reports, figure tables in the results report, contract and budget documents) conflict with stakeholders' after-the-fact statements (denials or explanations in interviews), give the official record more weight unless a document supports the statement. Do not treat both as equally weighted "hearsay" and raise the score.
- A conflict **affects the score** only if choosing the other value would change that question's score by 0.5 or more. Otherwise register it with "no score effect" and leave the score as is. Simple reporting errors in the report (conversions, typos) are not penalties unless they change a factual finding.
- Use the local conflict-ID prefix defined in your evaluator file (for example `REL-X1`). The verifier assigns global `X` IDs.

## 4. Reading the source

- Do not read the whole source from start to finish. The converted copy of a 137-page report is about 180,000 tokens and does not fit in one context together with instructions and output.
- Start from the ledger and page index when provided. Otherwise locate passages with Grep and Read only the pages you need.
- Keep each Read to 300 lines or fewer (fewer when large tables are present). A single Read cannot exceed 25,000 tokens.
- Re-search for counterevidence and conflicts across the whole document with Grep.
- Do not create or modify files (read-only).

## 5. Independence

- Rate in a new context without inherited parent history: Codex uses `fork_turns: "none"`; Claude uses a fresh registered evaluator without resuming a session.
- Use the frozen `source-pack.md` and supplied hash. If another criterion's results or the parent's expected grade are supplied, report an **isolation violation** and do not rate from that input. Re-rating also starts in a new context.

- Evaluate only your assigned criterion. Do not guess or mention other criteria's scores, conclusions, or expected grades.
- If the delegated material contains other criteria's scores, do not use them, and report that in the limitations.

## 6. Shared output structure

Follow your evaluator file's output format and always include:

1. **Rating by key question** table — columns: Key question · Finding · Score (1–4 / cannot evaluate / N/A) · **Fact ID** · Supporting evidence and source location · Counter/constraint evidence · Conflict ID · Evidence status
2. **Source-conflict candidates** table — columns: Local ID · Issue · Value/statement A (location) · Value/statement B (location) · Effect on score/finding · Follow-up needed
3. **Fact-ledger additions** table — columns: F-ID (existing/new) · Fact key and definition · Value/status · Unit · Denominator/population · Reference period · Aggregation rule · As-of date · Document·version · Source location · Reason. If there are none, write "No additions".
4. **Criterion summary (draft)** — criterion rating (formula and per-question scores), evidence-confirmed and cannot-evaluate parts, strengths and weaknesses, limitations
5. **Improvement recommendations**

- Evidence-status labels are `confirmed / needs qualification / inconsistent / no evidence / cannot evaluate`. They are DevEval operating labels, not official KOICA scores.
- Never omit counterevidence, conflict candidates, or unevaluable items for concision.

## 7. Authoritative question-score JSON (the five composite criteria)

After the narrative, evidence, conflicts and ledger additions, return exactly
one `json` fenced object for your criterion. Do not write files. The lead saves
the response unchanged and the collector reads the JSON. Impact is excluded.

- `criterion`: `relevance/coherence/effectiveness/efficiency/sustainability`.
- `questions`: `q1`, `q2` (Effectiveness also `q3`), each with `id`, `status`,
  `score`, `fact_ids`, `reason`.
- `status`: `scored`, `unavailable`, `not_applicable`. Scored questions need a
  numeric score from 1–4 in half-point steps and at least one F-ID. Otherwise
  score is `null` with a reason for exclusion. No NaN, numeric strings, means,
  totals or grades in the input.
- `fact_ids` is an array such as `["F1", "F2"]`, without marker syntax. Propose
  new facts in the ledger-addition table first; do not finalize a score based
  solely on a fact that has no global F-ID yet.
- Default `aggregation` is `mean`. A weighted form needs `weighted_mean`, a
  cited `weight_basis`, and positive question `weight` values summing to 1.
  Follow the lead's `koica-legacy-weighted` profile when Relevance needs q3.
- Optional `summary` and `conflict_ids`. Before verification, retain the
  criterion's own local IDs (REL-Xn/COH-Xn/EFF-Xn/EFI-Xn/SUS-Xn) or already
  assigned global IDs. The verified authority permits only global X-IDs.
  Never delete a material conflict just to satisfy formatting.
- Mark the criterion rating **pending code calculation**. See
  `<root>/docs/score-contract.md` and `<root>/templates/score-input-template.json`.
  The template's `pending` status is invalid and must be filled before return.
